Контракт §4/§6/§14 обязателен:
1. Типы и чистые applyGroupOp/normalizeGroupName; подтверждение содержит confirmedFor, операция confirm принимает proposalKey. Ключ текущего предложения стабилен при пересчёте без изменений, не зависит от случайных Expense.id/времени/confirmed и меняется при релевантной правке данных с теми же rawIndices. Старый ключ не разрешает новое слияние.
2. AnalyzeOptions.groups и AnalyzeResult.sources/groups аддитивны. sourceIndices строятся из фактических объектов, не обратным поиском банковских ID. Невалидные/неоднозначные sourceIndex не должны приводить к молчаливому выбору и двойному учёту.
3. Глобальные exact dedup/refund/credit-фильтры действуют до назначений. Split изолирует выбранную корзину. Merge действительно соединяет разные нормализованные имена под внутренним ключом, не мутируя исходные транзакции и не теряя части, которые раньше describe отбрасывал.
4. Для Merge последовательных частей одна последняя цена и одна частота; не суммируй две цены одной подписки. mixed_periods/overlapping_services — rejected. Принудительный скачок >1.5× через разрыв требует подтверждения актуального предложения. Разрыв отражается в evidence и ограничивает confidence до medium. name — подпись, не доказательство регулярности.
5. Только applied расходует строки группы. Для rejected/needs_confirmation/inactive строки остаются в корректном автоматическом пуле без пропусков/двойного включения. Неактивная группа не означает applied. Ошибки groups дают отчёты, не исключения всего анализа.
6. Без groups и с groups=[] прежние expenses/stats/итоги сохраняются; default detector не переписывай ради исправления незаданных случаев. Действующие формулы integer cents, cap, newId, opaque IDs, lifecycle и приватность сохраняются.

Обязательные регрессии:
- Split одинаковых списаний двух Netflix-аккаунтов без реального ID → 2 расхода, 37176 ¢/year;
- Merge двух последовательных фрагментов Netflix → 1 расход, 18588 ¢/year;
- Merge Netflix/NFLX под разными именами; evidence и источники не теряются;
- Adobe 999/1999 monthly параллельно → overlapping_services, автоматический итог 35976 ¢;
- mixed_periods; большой скачок до/после confirm;
- подтверждение устаревает после Edit суммы/даты с прежними rawIndices и изменения активного состава;
- sourceIndex и неуникальные банковские IDs; исходные данные не мутируются;
- перестановки txs с сохранёнными sourceIndex; exact дубли с детерминированным представителем;
- невалидные группы, перенос строк, undo/clear, лимиты, sources/expenseIds и автоматический fallback.
