## Задачи

1. **F04 — готовность импорта.** После valid CSV → файл >5 MB старый результат не должен анализироваться под видом нового. Блокируй Analyze при ошибке, чтении/парсинге, изменении ещё не предпросмотренного текста или отсутствии актуального результата. Передавай readiness/error родителю. Старые file.text()/таймеры/parse jobs не должны перезаписать новый ввод или восстановить данные после Delete. При этом частичный импорт валидных строк остаётся доступным после завершённого предпросмотра. Отмена устаревшего job должна работать и при unmount.

2. **F05 — невалидный target.** Сейчас $10 → `oops` оставляет в store target=$10 и potential $65.88 для Netflix $15.49. При пустом/невалидном текущем вводе вызывай существующий `setTargetPrice(id, undefined)`, показывай понятную ошибку для невалидного значения. Не сохраняй невидимую старую экономию. Свяжи сообщение ошибки с input через aria-describedby.

3. **F10 — действие доступно без ожидания AI.** Локальный fallback должен отображаться и копироваться сразу; запрос AI может улучшить его в фоне. Добавь клиентский deadline не больше 9 секунд с корректным cleanup; HTTP/network/schema failure сохраняют рабочий Template. Не принимай устаревшие ответы. Изменение attempted/completed/reported price не должно повторно вызывать AI: зависимость только от полей запроса, tone и явной Regenerate. Не добавляй запросы на каждый рендер. В этой волне не меняй политику очистки merchant и не импортируй будущие backend helpers: её интегрирует куратор следующим заданием после проверки контракта.

4. **F02 — единое отображение reported.** В карточке действия не считай reported независимо как `price * multiplier`. Используй существующий money engine `computeTotals([expense])`, чтобы summary и карточка совпадали. Исправление жизненного цикла completed выполняет backend; не дублируй его в UI.

5. **F13 — происхождение sample.** Load sample CSV и Paste sample rows должны сохранять Sample data на results и action. Передай provenance через локальные props/callbacks; используй существующий `startSession(expenses, { isDemo })`, не меняй shared types/store. Реальный пользовательский CSV не должен маркироваться Sample data.

6. **F15 и yearly warning.** Замени абсолютные «Nothing is uploaded / Everything stays in your browser / Local-Only» на точное объяснение: CSV/строки обрабатываются локально; при AI-генерации сервер получает минимальные поля одного расхода. Упоминание должно быть видно до первого POST. Не обещай, что AI никогда не ошибается. Сохрани смысл «проверить и связаться с поставщиком самостоятельно». Для yearly покажи рядом с действием: `Billed yearly: savings may start at your next renewal.` Согласуй затронутые формулировки README. Не пиши, что transaction IDs уже удалены из localStorage: такой реализации пока нет.

7. **F14 — небольшие исправления доступности.** Для мелкого зелёного текста обеспечь контраст ≥4.5:1 на фактических фонах, сохрани текущий стиль. У tone/status radio groups и message tabs реализуй стандартную навигацию стрелками, focus/tabIndex и необходимые ARIA-связи. Без редизайна и новых UI-зависимостей.

Не включай в эту волну полную перегруппировку CSV, полноценный PDF, share, аккаунты или analytics. Зафиксируй оставшиеся ограничения честно.

## Проверки и приёмка

Добавь осмысленные E2E-регрессии в свой новый файл:
- valid CSV → oversized CSV: Analyze недоступен, прежний результат не используется;
- target $10 → invalid: старый target удалён из persisted state, старая potential исчезает;
- sample CSV/paste → результаты с Sample data; обычный CSV без метки;
- зависший AI: Template и Copy доступны сразу;
- status/reported edits не увеличивают число AI POST;
- Delete во время незавершённого импорта не восстанавливает очищенные данные.

Проверь текущий demo до Copy и мобильные 360/375 px, включая заполненный preview и ошибки. Не делай настоящих LLM-запросов: используй пустой ключ или сетевые mocks. При браузерной проверке следуй правилам доступных инструментов; если выполнить её нельзя, сообщи это.

Запусти `npm run typecheck`, `npm run lint`, `npm test`. Production build/E2E не запускай параллельно с таким же прогоном другого агента: если общая build-директория занята, сообщи, что эта проверка отложена; итоговую интеграционную проверку выполнит куратор. Не маскируй чужой сбой как свой PASS.
