## W2F1 Старая ссылка молча выбирает другое действие

Средняя важность. [action-workspace.tsx:767](/Users/nuras/Desktop/businesscup/src/components/action/action-workspace.tsx:767).

При отсутствии запрошенного ID activeExpense возвращает actionExpenses[0]. На production-сборке воспроизведено: загрузить demo, открыть `/action?id=exp-00000000000000000000000000000000`. Открывается Streaming A, появляется Copy и автоматически происходит один POST /api/ai/action для чужого относительно ссылки расхода.

Это особенно заметно после миграции старых IDs и повторного импорта. Новый случайный ID не указывает на другой расход в store, но UI сейчас всё равно подставляет другой расход. Поэтому утверждение «старая ссылка не откроет другой расход» требует frontend-исправления.

Нужно различать `/action` без ID (первое действие допустимо) и явно переданный, но отсутствующий/непригодный для action ID (Not found, без ActionDetail и без POST, возврат к Review). То же поведение для `/action/[id]`. Локальный selectedId не должен игнорировать новый ID из URL.
